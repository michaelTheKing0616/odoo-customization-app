# New features index (Tope's brief, 22 Oct)

Status: **scope approved 22 Oct** (DEC-050, DEC-051). Backend-safe cards may start early in the NF worktree stream (`ORCHESTRATOR_PROMPT.md` § Parallel worktree); UI cards release with their phase at G2. DEC-052..074 stay open and block only the cards they name.

- Design per epic, sections 1–7 (user and job, UX, UI, security, robustness, data/API, risks/DEC): `docs/build-plan/new-features/<GROUP>.md`. Shared rules: `new-features/00_BASELINE.md`.
- Cards: `cards/phase-<N>/<PREFIX>-*.md`, generated by `tools/build_nf.py` from `tools/nf_data.py` (marker line `NF:`; Prep edits that delete the marker are never overwritten).
- Order inside every epic: contract → storage → engine(s) → live 17–20 → ui-spec → ui-build → e2e → visual. Each card is one reviewable change (XS–M).
- Owner tags: `Owner: backend-safe` (contract, storage, engine, live, eval; no screen or component) or `Owner: UI` (spec, build, e2e, visual, and the in-Odoo addon panel).
- Ledger: one `NF-<CARD>` row per card plus one `NF-EPIC-<CODE>` row per epic. Decisions: DEC-050..074 in `09_DECISIONS_FOR_TOPE.md`.
- Brand: `docs/brand/README.md`. The brief's `docs/brand/ingenium-v2/` does not exist in this repo.

## Risks across the set

- Effort: 269 new cards is about a third more plan (847 before). Phase weights (`budget.json`) stay as they are until DEC-050; the Orchestrator re-weights at G2 per phase.
- Facts that change with law (Nigeria) or vendor docs (Paystack, Flutterwave, FIRS/NRS) are data with sources, behind Gate A; no card hard-codes them.
- Sandbox capacity (UPG, S2C, MANUAL): one rehearsal per workspace, 2-hour cap, own ports 8101+.
- Seventeen storage cards add App DB tables; each is L3 with oracle round-trip tests. They can be batched per phase into one revision at Prep if Alembic heads conflict.
