# 01_REVIEW — independent "what could be wrong?" review of the App Studio Pack (21 Oct 2026)

Reviewer: independent (did not author the Pack). Scope: `00_PACK.md`, `ORACLES.md`, `CODE_MAP.md`, 38 `AS-*` cards, against the code read today. Read-only except this file. `holdout_fresh/` not opened.

**Verdict: the diagnosis is sound and the direction (owner words only, structure from a verified ledger, deterministic compile, total outcome) is right. The design is not buildable as carded: 3 blockers (card dependency cycle around AS-TOTAL/AS-COMPILE, the contract/checklist call is neither in nor out of v3 so `declined`/`option_a`/hosting limits have no producer, and character-offset spans + per-clause coverage make the ledger call slow and fragile). Fix those and the 11 majors before any Grok worker starts.**

## 3. Attack notes not in the table (for the planner)
- Removing gap-fill makes small briefs thin: salon_voice compiles to one 5-field model with no status, no sequence, no views beyond defaults. FIX_PLAN rule 3 licensed "missing views, menus and fields on the owner's own records"; v3 P is labels/help only. Tope's ≥ 8 rating bar will feel this first. Add a deterministic hygiene pack (name, active, company, state only when a rule implies it) recorded as assumptions.
- "Conservative = fold" does move error into false folds; the honest part is `promote_recoverable`. Make the X2 gate read false folds **after** defaults but report both ITT and promote-recoverable so a fold-heavy prompt cannot hide.
- Threads cannot be cancelled: pass `timeout_s ≤ hard deadline` into every provider call, or the pool keeps burning quota after `degraded` is returned.
