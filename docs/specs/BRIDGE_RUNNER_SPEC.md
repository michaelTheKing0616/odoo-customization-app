## App-wide: LLM caching (Tope priority, Oct 16)
Cache every LLM call app-wide to cut cost: (a) audit all AI call sites into one shared AI client; (b) exact-response cache keyed on model + prompt + inputs + Odoo version/snapshot hash, with TTL and invalidation when the snapshot changes; (c) provider prompt/context caching (Vertex/Gemini cached content) for big stable prefixes (system prompts, catalogs, schema snapshots); (d) a semantic cache for near-duplicate questions where safe, with a confidence floor; (e) cache deterministic sub-results (schema summaries, mappings, explanations) per database; (f) batch calls; (g) a cost dashboard showing hit rate and money saved; (h) never cache secrets or personal data; bypass with a "fresh answer" button. Do this early, before new AI features.

## App-wide: AI input/output guards (approved by Tope, Oct 17)
Today: output side strong (rpc_classify A/B/C, rpc_guard, ai_draft_validators, money guard, approvals, anomaly_guard, mcp_guard read-only). Input side thin (phrase list in agent_runtime/runtime.py, SK-META-INJECTION rule, llm_gateway/scrub.py logs only).
1 Injection classifier: small fast model on all untrusted text (uploads, BRDs, record text, Bridge payloads, website content, client chat) before the main AI; untrusted text always fenced as data; flag, never follow. Replaces the phrase list (meaning, not word lists).
2 PII/secret redaction before any cloud AI call (names, phones, emails, bank details, keys), restored after; backs D6 consent.
3 Output checker: no secrets, other-client data or prompts leaked; Demo Co-Pilot answers carry honesty labels; "exists in your DB" claims verified against the DB.
4 Topic guard for client-facing chat (Odoo/business scope, polite abuse handling).
5 Every flag logged to History; red-team test pack runs before each release.
All in the shared AI client, cached, cheap; live 17-20.
